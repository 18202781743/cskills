# 统信 OA 工时填报

处理用户指定日期和任务的工时，从工作事项整理到草稿回读；符合提交条件时再提交并回读。使用当前 API 会话，不用截图坐标或手工点击。接口字段、计算边界和请求顺序见 [接口记录](references/har-contract.md)；执行写请求前读该文件的“保存与提交”“按周工作内容”“API 执行顺序”。

## 默认流程

1. **认证并读取。** 运行 `python scripts/auth_session.py check`。业务调用在同一进程中导入 `authenticate_shared()`，用其 OA Session 和 BI token 查询目标周现有工时、OA 考勤月历、应填时长及项目任务。没有共享凭据时，在交互终端运行 `python scripts/auth_session.py setup`；不能安全交互就告知用户如何完成，不收集聊天中的密码。认证格式和接口见 [共享认证流程](references/har-contract.md#共享认证流程)。
2. **整理逐日记录并沿用任务。** 依据 `Asia/Shanghai` 确定相对日期和周一至周日。每天一条 `YYYY-MM-DD 工作内容，`，同一天的多个事项用分号合并；内容无须拆成逐小时记录。用户未指定改任务时，优先沿用此前确认的项目/任务（例如 DDE(V25 2500u2)），核对其当前仍有效即可；不要依据“V20”“Qt 6”等工作内容关键词另选任务或要求用户分配各事项的小时数。用户明确指定多个任务时，才分别确定工时。未给当天总小时数时，从当前考勤月历经标准输入运行 `python scripts/calculate_hours.py --date YYYY-MM-DD`；计算规则见 [考勤打卡与工时计算](references/har-contract.md#考勤打卡与工时计算)。
3. **解决真正的缺项。** 只有既无用户指定任务也无可信的已确认默认任务、多个明确任务缺少各自工时、缺下班卡、请假、异常打卡或脚本返回 `status=review` 时，才请用户补充必要信息。用户给的当天总时长与有效考勤计算值不符时，报告差异并请其确认；已确认的异常工时无需重复询问。已提交、审批中或已审批的记录不直接改写。查询不全或请求字段无法确认时不写入。
4. **合并当周内容。** 读取所选任务目标周当前 `workContent`，保留目标周全部有效条目，把本次当天事项追加到该日；相同内容去重。若文本混有上周或其他周日期，只从**本次要保存的目标周文本**中清除跨周行，不改动其他周已保存的记录。确定周范围、日期、沿用的项目/任务/阶段、打卡时间、当天总工时及依据、将保存的当周工作内容全文。缺项已解决就继续保存，不以展示预览为由暂停等待用户回复。
5. **直接保存或续写草稿并回读。** 先确认目标日期在所选任务下有无记录：已有可编辑草稿时沿用其 ID 和当前字段更新当周内容，不能以 `id=null` 再建一条；无记录时才新建。信息完整后在本轮调用 `POST /oa-bi/sys/sysworkhour/save` 保存 `status=0`，不询问是否保存。若接口报“项目/任务/日期数据不允许重复”，先按 [重复记录排查](references/har-contract.md#重复记录排查) 查找已有记录和正确的更新字段；不要仅凭一次空列表推断数据不一致或让用户去 OA 检查。保存后重新查询，核对日期、记录 ID、小时数、当周 `workContent` 和草稿状态；确认当周旧条目未丢失且跨周文字未混入。无法确定已有记录 ID 或状态时停止写入并报告具体障碍。
6. **提交前确认。** 草稿回读成功后报告已保存结果。只有用户随后明确确认提交，才用回读后的 ID 和当前字段提交 `status=1`，再回读确认状态。用户在初始请求中说“保存并提交”或“直接提交”时，也先保存草稿并回读，然后单独询问是否提交；“仅保存”请求到草稿为止。`code=0` 不能代替回读。
7. **回复结果。** 列出日期、项目任务、逐日小时数、完整工作内容及实际保存/提交状态；未完成时说明具体缺项。不要输出工号、审批人 ID、Cookie、token 或其他身份信息。

## 关键边界

- “帮我写今天的周报，内容是……”也进入上述 OA 填报流程。当天尚无下班卡时，先请用户给出实际工时；不能默认 8 小时。
- 同一任务可以持续数周或数月；默认只编辑目标周内容。目标周文本中的跨周默认行可以清除，目标周已有有效内容须保留。用户要求改写目标周既有条目或已提交记录时，先验证当前记录的可编辑状态和接口契约；本 skill 的接口记录未验证撤回 API，不能猜测撤回请求。
- 认证后的 OA Session 只用于 OA 请求，BI token 只放在 BI 请求的 `token` 头。历史 HAR 仅供契约核对，不从中重放 token、工号或个人数据，也不把当前响应落盘。
- 本地机的通用 HTTPS 代理可能使内部 OA TLS 失败；认证脚本默认直连，可用 `AI_UT_PROXY` 指定代理。不要禁用证书校验。
